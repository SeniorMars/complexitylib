### What the revision changed

- **The counter handles constraint systems, not just 3-CNF.** Every variable
  lies in at most three scopes, arity is at most `c₁ log₂ N`, and tables may
  be integer-valued (Remark `rem:weights`). Constraints enter through the
  multilinear extensions `Φ_e`, and the system is read through an oracle, so
  it is never stored. Bounded-occurrence 3-CNF is a special case.
- **Machines become constraint systems with no circuits.** Each
  Hopcroft–Paul–Valiant interval of `b ≈ log t` steps is one constraint
  (`lem:virtual`). The system has `N = O(t)` variables, each in at most two
  scopes. Pippenger–Fischer circuits and Tseitin encoding are gone. The
  simulation space is now `κ(t) = t(log log t)²/√log t`.
- **Kintali's construction is reproved** in Appendix A for parameters that
  grow with `N`, so the paper is no longer conditional on it.
- **There are no preprocessing tables.** `A[u,w]` comes from the explicit
  spectral formula (eq. `Aentry`) with an explicit interpolant `f`.
- **Supports have a new encoding.** Marked supports `η ∈ {0,+,−}^N` use a
  per-segment code of length `⌈N/s⌉ + (k+2)|η|`, replacing the Elias gamma
  code plus the separate `U` mask.
- **Parameters:** `s, r, Q, R, D` are unchanged and `τ` is dropped. Balance
  now needs `4D² ≤ M` and `(Δ+1)r^{-Q} ≤ 1`. There are at most `12N/s⁷`
  measurements per node, and `y` takes at most `30Nk²/s⁵` bits.
- **Appendix B gives pseudocode** with three explicit buffers (`ETA`, `Y`,
  `X`), their writers and their lifetimes.

### Formalization strategy (revised for speed)

The key observation: Complexitylib's `CounterProgram`
(`Complexity/.../LogSpace/CounterProgram.lean`) already proves the five
`QueryMachine` callback certificates for every counter program, on every
configuration, in space linear in the binary register lengths
(`Simulation.query_inSpace`, `exec_inSpace`, `emitted_inSpace`,
`halted_inSpace`, `finish_inSpace`). Only the convenience theorem
`computableInLogSpace` restricts registers to `(n+1)^d`. A register may hold an
arbitrarily large natural number, so a buffer of `Λ` bits is just a register
below `2^Λ`. Counter programs also read the original input at a computed
position (`read e`).

So the remaining machine work does not need new hand-written machines or
certificates. The plan:

1. Big-register compiler theorem. Restate `computableInLogSpace` and
   `computableInLogSpace_of_reaches` with the register bound
   `(n+1)^d` replaced by `bitlength(r) ≤ c·S(a)`. Feed the existing global
   certificates to the general `QueryMachine.computableInSpace` with our
   input-indexed budget adapter. This is small: a few dozen lines on top of
   existing lemmas.
2. A structured front end. Add a small language (assignment, sequence,
   if, while, and subroutines inlined as macros) that compiles to
   `CounterProgram` code at label offsets. Prove Hoare rules for it from
   `CodeAt` and the existing `Reaches.assign/lt/read` lemmas. This is a
   one-time investment; check first whether Complexitylib already has one.
3. Transcribe Appendix B as one structured program over the actual input
   `x`:
   - The buffers `ETA`, `Y` and `X`, the seed, a stack for `COEFF`, and the
     schedule `π` are registers. Field access is division and remainder by
     powers of two.
   - Table entries read `x` directly with `read`, so no oracle-composition
     bridge is needed.
   - The interval constraints are evaluated by inline code that simulates
     `b` steps of the fixed machine `M`, generated from `M`'s finite
     transition table.
4. Prove correctness subroutine by subroutine. Each subroutine has a
   pre/postcondition stated against a Lean-level specification. Loop
   invariants are partial `Finset` sums of the master formula, and the
   algebra from M1 connects the final value to the count. Register bounds
   follow from the same invariants.

This replaces the per-routine `QueryMachine` plus `HaltingBudgetCompiler`
approach for the rest of the work. The existing component machines
(Hermite, gamma, support) become optional. Their algebraic specifications are
reused, and their arithmetic is easier to rewrite as structured code than to
compose. Their verified semantics are not wasted.

Other ways to save time:

- Use weighted constraint systems throughout (`ZMod p` or integer tables).
  Complexitylib's block-network tensors count coin strings per interval, so
  they become tables directly. CNF is a corollary.
- Prove the algebra once against an abstract interface: factors that are
  multilinear in their inputs and agree with the table on Boolean points.
  Port only the modules on the critical path.
- Make the program parametric in `(s, k, Q, R, D, p)`, so it can be run
  in Lean (`#eval`) with toy parameters and compared with brute force before
  any proof. The asymptotic parameter choice is instantiated separately.
- Handle small inputs by patching finitely many inputs in finite control.
  Below the parameter threshold there are only finitely many `t`, hence
  finitely many inputs `x`, so no brute-force counter needs to be built. This
  needs one lemma: changing a decider on finitely many inputs preserves
  `DSPACE(f)`.
- Fix `t = c·n + c` from the `NTIME(n)` bound. Skip doubling, the
  almost-everywhere hierarchy, Chinese remaindering and the probabilistic
  corollaries.
- Write all bounds as explicit inequalities with constants, such as
  `state ≤ 100·N·k/s + C·log² N`. Only the final step uses an asymptotic
  lemma, `κ(n) = o(n)` from `ParameterAsymptotics`.
- Once the front end exists, subroutine proofs are independent and can be
  done in parallel, with cheaper models for routine arithmetic invariants.

- M0. Check the reuse assumptions before investing.
  - Import Complexitylib's `Probabilistic/*`, `Counting/*` and

  - Confirm that `CountingSimulation` is stated for CSLib's `NTIME`.
  - Look for an existing structured front end over `CounterProgram`.
  - Prove the big-register compiler theorem (step 1).
- M1. Generalize the algebra to weighted constraint systems of arity `Δ`,

  for some `π` and some `i ≤ t`.
- M3. Build the structured front end with Hoare rules (step 2), then write

- M4. Prove the subroutine contracts, termination and register bounds

## Goal

Formalize the manuscript's exact-counting construction and its actual machine
workspace bound, then prove the nondeterministic simulation and derive

\[
\mathrm{NTIME}(n) \subsetneq \mathrm{DSPACE}(n).
\]

The central outstanding theorem is a concrete deterministic machine that
counts, modulo a prime, the satisfying assignments of a bounded-occurrence
weighted constraint system of logarithmic arity, using

\[
O\!\left(\frac{N(\log\log N)^2}{\sqrt{\log N}}\right)
\]

work space, with the required time bound on the same machine. A correct
arithmetic expression alone does not establish this resource theorem. The
simulation then gives `NTIME(n) ⊆ DSPACE(O(κ(n)))`, where
`κ(t) = t(log log t)²/√log t`.

**The separation is not yet proved. The goal remains active.** We will not
assume the novel counting algorithm or its workspace guarantee as an axiom.

## Current work and known gaps

- The gamma-prefix query machine and its five callback-space certificates are
  included in the complete checkpoint. Its state uses an explicit injective binary codec,
  and the compiled validity machine has simultaneous `2^(C*(n+2))` time and
  `C*(n+2)` workspace. The bounded reader below supplies the sharper logarithmic
  bound; support/formula composition remains.
- `HermiteCoefficientMachine.coefficient_simultaneous_bits` completes the
  concrete Hermite coefficient component. All five scalar parameters are
  runtime binary input. The factor accessor computes consecutive-node values
  directly, only when an occupied leaf needs them; no factor list or function
  oracle is supplied to the machine. Every continuation and temporary callback
  argument is charged. The explicit serialized budget is at most
  `256*(log₂ p+1)²`; compilation introduces a fixed multiplicative constant.
- `HaltingStateCompiler` tests for termination on each round without carrying
  a runtime fuel counter. Its initializer is itself compiled, so input-dependent
  state is not hidden in finite control. Independent review checked empty-word
  tagging, immediate termination, composition storage and proof-only time
  witnesses. The promise-domain endpoint guarantees behavior on valid encoded
  inputs, not termination on every malformed binary string.
- The
  `HermiteCoefficientCorrectness.weightCoefficient_simultaneous_bounds` already
  connects the same compiled machine to the actual recovery polynomial
  coefficient under `Q<p`, `0<order≤p`, and `index<order`; this identification
  is proved, not assumed. Lists and trees appear only in its proof.
- `HermiteWeightMachine.polynomialWeight_simultaneous_bounds` completes full
  weight evaluation with the same quadratic-bit workspace. A descending loop
  accumulates one recomputed coefficient times a modular power per iteration.
  `HaltingBudgetCompiler` explicitly charges both retained state and callee
  workspace. The outer state has at most `31L` bits and its state-plus-callee
  budget is at most `63L²`, where `L=log₂ p+1`; machine constants also include
  compilation. Independent review found no hidden oracle, runtime clock or
  input-dependent finite control. Scalar order zero halts immediately; the
  polynomial endpoint currently requires positive order. Recovery and Taylor
  data/formula loops remain to be composed.
- `BoundedGammaPayload.read` now returns `Option (value,nextCursor)` with exact
  cursor semantics and bounded registers for arbitrary malformed payloads too.
  Prefix room is halved; payload overflow is checked before accumulation.
  `BoundedGammaPayloadSpace` compiles initialization, guarded append, transition,
  query, halt and output on their complete encoded arguments. The runtime
  bound is charged explicitly. All-prefix state/transition encodings are at
  most `9*(B+C)` / `27*(B+C)` bits, where `B=log₂ bound+1` and
  `C=log₂(max(start,input length))+1`. The finite semantic driver is now linked
  to an actual input-query machine by `BoundedGammaQuery`.
- `BoundedGammaQueryMachine.read_simultaneous_bounds` completes the bounded
  reader on packets `((bound,start),payload)`. `SmallHeaderProjection` uses a
  zero-work-tape transducer to emit just the framed header; the payload is
  scanned read-only. `InitializedQueryCompiler` runs that certified initializer
  and then queries the original input. With `D=B+C`, header length is at most
  `2D`, the complete scan/initialization budget at most `6D`, and every parser
  state at most `22D`. The endpoint charges compiler and callback constants,
  proves joint `2^(K*D)` time / `K*D` workspace, and separately bounds the
  encoded output by `3D` for composition. It covers zero bounds, malformed
  payloads, and oversized cursors on all valid encoded packets. Arbitrary
  malformed outer binary encodings are outside the encoded-input theorem.
- For a start cursor within the payload, the reader's proved workspace is
  `O(log(bound+1)+log(payload length+1))`. Repeated support/formula reads must
  share the original read-only input. Constructing a fresh packet by copying
  the complete formula would lose the intended space bound.
- `BoundedSupportQueryMachine.cardinality_simultaneous_bounds` now completes
  the full-support validator/cardinality reader. It retains `(N,capacity)`,
  cumulative index, rank, cursor and one gamma state. EOF accepts only at a
  codeword boundary; every other successful running step consumes exactly one
  bit. The core halts within `payload.length+1` query steps and equals the
  existing whole-support specification, including rejection of invalid tails.
  The actual machine charges initialization, all callback scratch, scan counter
  and output. For `D=(log₂ N+1)+(log₂ capacity+1)+(log₂ payload.length+1)`, core
  state length is at most `20D`, complete transition arguments at most `44D`,
  query state at most `40D`, and compilation budget at most `6D`; machine
  constants additionally account for compilation. A successful scalar result
  is the unique valid support's length, not its capacity. The theorem covers
  all payloads under canonical encoded headers.
- Next, add validated ordinal lookup by retaining one hit ordinal and continuing
  to validate the remaining input. Connect subset masks using the actual
  returned cardinality. Generated compressed candidates may occupy their
  charged compressed storage; do not materialize a complete formula to create
  an input packet.
- Continue the same explicit encoding and global callback discipline for
  compressed supports, measurements, schedules, and formula evaluation.
- **Input-head convention.** The revised paper fixes a right endmarker that
  the input head cannot pass. The Lean route does not depend on this: the
  simulator is compiled by `QueryMachine` on CSLib's own input tape, and the
  semantics come from Complexitylib's CSLib-based reduction. Confirm this
  when importing in M0.
- **Pippenger–Fischer local access is no longer needed.** The revision
  replaces circuits with one constraint per interval.
- **Choice strings versus computations.** Complexitylib's
  `Counting/Certificate` and `ChoiceTable` prove the bijective correspondence.
  For deciding `NTIME`, positivity of the choice-string count suffices either
  way.
- **Kintali's construction for growing parameters** is now proved in the
  paper's Appendix A. Lean already has the matrix locality and the spectral
  tail; it still needs eq. `Aentry` and the arity-`Δ` schedule bound (M1).

## Completion standard

Completion requires the concrete counter and its actual resource theorem, the
parsimonious simulation, and the final strict-containment theorem in matching
machine models. All required assumptions must be discharged, and the final
theorems must check without `sorry` or unproved user axioms. A conditional
hierarchy corollary, a green check on algebra alone, or passing tiny examples
does not meet that standard. Independent complexity-theory review remains
valuable for the statement/model correspondence and novelty.
